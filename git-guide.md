# 🚀 Git: От локального до облачного репозитория
*Полное руководство по работе с Git и GitHub*

====================================

📋 1. НАСТРОЙКА GIT (ОДИН РАЗ)
--------------------------------
```bash
git config --global user.name "Ваше Имя"
git config --global user.email "ваш@email.com"
git config --global core.editor "code --wait"  # Для VS Code
```

🏁 2. СОЗДАНИЕ НОВОГО ПРОЕКТА
-------------------------------
# Способ A: С нуля
```bash
mkdir проект
cd проект
git init
```

# Способ B: Из существующей папки
```bash
cd существующий_проект
git init
```

🔗 3. ПОДКЛЮЧЕНИЕ К GITHUB
---------------------------
# Создайте репозиторий на GitHub.com (без README!)
# Затем подключите:
```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/РЕПОЗИТОРИЙ.git
git branch -M main  # Переименовать ветку в main
git push -u origin main  # Первая отправка
```

🔄 4. ЕЖЕДНЕВНЫЙ РАБОЧИЙ ЦИКЛ (ВИТРИНА!)
-----------------------------------------
# 📍 Шаг 1: НАЧАЛО РАБОТЫ (всегда сначала!)
```bash
git status                     # Проверить где я
git pull origin main           # 🔥 ЗАБРАТЬ СВЕЖИЕ ИЗМЕНЕНИЯ!
```

# 📍 Шаг 2: РАБОТА НАД КОДОМ
# Создавайте/редактируйте файлы...

# 📍 Шаг 3: ПОДГОТОВКА КОММИТА
```bash
git add .                      # Добавить все изменения
# ИЛИ выборочно:
git add index.js styles.css    # Конкретные файлы
```

# 📍 Шаг 4: СОЗДАНИЕ КОММИТА
```bash
git commit -m "Описание: что сделано"
# Формат: Глагол + что сделано
# ✅ "добавлена авторизация"
# ✅ "исправлена ошибка в расчетах"
# ✅ "обновлен README"
```

# 📍 Шаг 5: ОТПРАВКА НА GITHUB
```
git push origin main           # 🔥 ОТПРАВИТЬ ИЗМЕНЕНИЯ!
```
⚠️  ЗОЛОТОЕ ПРАВИЛО GIT:
-----------------------
```bash
ПЕРЕД работой → git pull origin main
ПОСЛЕ работы  → git push origin main
```
📊 5. ПОЛЕЗНЫЕ КОМАНДЫ ДЛЯ ДИАГНОСТИКИ
---------------------------------------
```bash
# Проверка состояния
git status                    # Что изменилось?
git log --oneline            # История (коротко)
git log --oneline --graph    # История с графиком
git diff                     # Что именно изменилось
```
# Информация о подключении
```bash
git remote -v                # Куда пушим?
git branch -a                # Все ветки
```

# Просмотр изменений
```bash
git show                     # Последний коммит
git diff --staged            # Что будет в коммите
```

🛠 6. ИСПРАВЛЕНИЕ ОШИБОК
------------------------
# Отмена неправильного коммита
```bash
git reset --soft HEAD~1      # Отменить коммит, оставить изменения
git reset --hard HEAD~1      # Удалить коммит и изменения
```

# Отмена изменений в файле
```bash
git restore файл.js          # Вернуть к последнему коммиту
git checkout -- файл.js      # Альтернатива
```

# Удаление добавленного файла из staged
```bash
git restore --staged файл.js
```

🚨 7. РАСХОЖДЕНИЕ ВЕТОК (САМАЯ ЧАСТАЯ ПРОБЛЕМА!)
------------------------------------------------
```bash
# Симптом: git push выдает ошибку:
# ! [rejected] main -> main (non-fast-forward)

# РЕШЕНИЕ:
git pull origin main          # 1. Забрать изменения
# Если конфликт → разрешить (см. ниже)
git push origin main          # 2. Отправить обратно

# Альтернатива (переместить ваши коммиты):
git pull --rebase origin main
git push origin main
```

⚔️ 8. КОНФЛИКТЫ СЛИЯНИЯ
-------------------------
```bash
# Когда появляется: Два человека изменили одну строку
# Как выглядит в файле:
<<<<<<< HEAD
Ваш код
=======
Код с GitHub
>>>>>>> коммит_хеш

# КАК РЕШАТЬ:
1. Открыть файл с конфликтом
2. Выбрать какой код оставить (или объединить)
3. Удалить маркеры (<<<<<<<, =======, >>>>>>>)
4. Сохранить файл
5. Выполнить:
   git add имя_файла.js
   git commit -m "Разрешен конфликт"
   git push origin main
```

🌿 9. РАБОТА С ВЕТКАМИ
-----------------------
```bash
# Создание новой ветки
git branch новая-фича        # Создать
git checkout новая-фича      # Переключиться
# ИЛИ одной командой:
git checkout -b новая-фича   # Создать и переключиться

# Слияние веток
git checkout main            # Перейти в main
git merge новая-фича         # Влить изменения

# Удаление ветки
git branch -d новая-фича     # Локально
git push origin --delete новая-фича  # На GitHub
```

---------------------------------


✅ 11. ЧЕК-ЛИСТ ПЕРЕД PUSH
---------------------------
```bash
1. git status              # Все ли файлы добавлены?
2. git log --oneline       # Правильные ли коммиты?
3. git pull origin main    # Есть ли новые изменения на GitHub?
4. Тесты проходят?         # Проверить работу кода
5. git push origin main    # Отправить!
```

🔧 12. ШПАРГАЛКА НА КАЖДЫЙ ДЕНЬ
--------------------------------
```bash
# УТРОМ:
git pull origin main

# В ТЕЧЕНИЕ ДНЯ (каждые 1-2 часа):
git add .
git commit -m "[тип]: описание"
git push origin main

# ВЕЧЕРОМ:
git push origin main  # Финальный пуш
```

📝 13. ТИПЫ КОММИТОВ (по соглашению)
-------------------------------------
```bash
feat:     Новая функция
fix:      Исправление ошибки
docs:     Изменения в документации
style:    Форматирование, точки с запятыми
refactor: Рефакторинг кода
test:     Добавление тестов
chore:    Обновление сборки, пакетов

Пример: git commit -m "feat: добавлена регистрация пользователя"
```

🎯 14. ЧТО ДЕЛАТЬ ЕСЛИ...
-------------------------
```bash
# ...залили node_modules/?
git rm -r --cached node_modules
# Добавьте node_modules/ в .gitignore!
git add .gitignore
git commit -m "fix: добавил node_modules в .gitignore"

# ...хотите переименовать коммит?
git commit --amend -m "Новое правильное описание"

# ...нужно обновить репозиторий без коммита?
git fetch origin  # Только получить информацию
git status        # Увидеть разницу
```

📞 15. ПОМОЩЬ И ДОПОЛНИТЕЛЬНО
------------------------------
```bash
# Справка по команде
git help команда
git команда --help

# Визуализация истории
git log --oneline --graph --all --decorate

# Красивый вывод
git config --global alias.lg "log --oneline --graph --all"
```

💎 ЗАПОМНИТЕ ГЛАВНОЕ:
---------------------
1. PULL перед работой, PUSH после
2. Коммитьте часто, пушите регулярно
3. .gitignore - ваш лучший друг
4. Конфликты - это нормально, их нужно разрешать
5. Git не удаляет код, он сохраняет историю
